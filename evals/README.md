# Forge 固定任务评测

评测当前的「规划 → 完整代码生成 → 静态校验 → 最多一次修正」流程，再在独立浏览器进程内执行预先固定的交互断言。线上 API 和评测共用 `runAppGeneration`，行为失败只记录结果，不额外调用模型修复，避免改变当前基线。

## 固定任务

第一版包含三条独立任务链、10 个步骤。每次重复都重新生成起点，后续修改使用本次上一步的完整代码。

| 任务链 | 新建 | 连续修改 |
| --- | --- | --- |
| Todo | 添加、完成、删除、空输入、中文长文本 | 深色主题 → 未完成筛选 → 编辑任务 |
| 计算器 | 四则运算、小数、操作数切换、清空 | 计算历史 |
| 内容排期看板 | 标题、状态、渠道、日期、状态变更 | 渠道筛选 → 逾期筛选 → 编辑标题 |

修改后复测已建立的旧行为和先前修改，主题也有独立断言。固定提示词指定可访问名称，检查使用真实输入、按钮和可见输出；这是该任务契约的测试，不代表任意自由需求的成功率。每个断言重新加载独立 iframe，断言内的动作共用同一状态。预览运行数据仍是内存数据，当前评测不宣称刷新后业务记录持久化。

## 执行

需要 Node.js 24，执行 `npm ci`。Windows 优先使用已安装的 Chrome / Edge；其他环境安装 Chromium：

```sh
npx playwright install chromium
```

可以通过 `--browser-path` 指定浏览器路径。首次先运行可信样例，验证任务、浏览器和报告链路，不调用模型或数据库：

```sh
npm run eval -- --mode fixture
npm run eval:verify
npm run eval -- --list
npm run eval -- --mode live --repeats 3 --max-calls 90 --dry-run
```

`eval:verify` 用临时本地 HTTP 模型响应验证修正、费用计算、预算停止、失败分母和浏览器错误 / 无限循环终止；它使用样例代码与模拟 usage，不调用付费模型。该检查需要允许本机 loopback 连接。

真实模型评测使用 `.env.local` 的现有模型配置（包括代理）；模型、协议、参数和 usage 会写入报告，密钥不会写入报告。完整运行 3 次重复，共 30 个步骤，正常 60 次调用，最多 90 次（包含无效代码修正）：

```sh
npm run eval -- --mode live --repeats 3 --max-calls 90
```

只运行部分任务时使用 `--tasks` 和 `--list` 中的 ID，以逗号分隔。选择修改会自动包含同一任务链的全部前置步骤。每次运行返回独立目录；可以用 `--out eval-results/baseline-v1` 指定新目录，已有目录拒绝覆盖。

生成总期限默认 120 秒，与线上相同；可用 `--timeout-ms` 在 1000–120000 之间调整。浏览器每任务总期限默认 45 秒，可用 `--browser-timeout-ms` 调整；浏览器进程超时后终止。任何失败、基线阻断或预算跳过使退出码为 1；只有全部预定任务通过才为 0。纯查看、预演不调用模型。

## 调用费用与预算

复制 `evals/pricing.example.json` 为 `evals/pricing.local.json`，填入你所使用模型的实际单价（每百万 token）、币种和可追溯价格版本。示例中的 `null` 是未知，不能直接当作免费价格。价格版本建议包含价格日期和来源；模型名必须与 `LLM_MODEL` 完全相同。

```sh
npm run eval -- --mode live --repeats 3 --max-calls 90 --pricing evals/pricing.local.json --max-cost 10
```

`--max-calls` 在每次规划、生成或修正之前检查，是调用次数的硬上限。`--max-cost` 是根据已返回 usage 和指定单价决定是否停止后续调用的阈值：一笔进行中的调用可能使总额越过阈值，因此它不是供应商账单的硬上限。指定费用阈值需要完整单价；某次调用缺 usage / 可计算费用时，停止继续调用。需要账单硬上限时，在供应商账户设置额度。

没有单价、模型不匹配、调用断线或缺 token usage 时，调用费用为 `null`。缺缓存用量而配置了不同缓存单价时也记未知；未配置缓存单价则全部输入按常规输入价格估算。失败、拒绝、截断和修正调用都包含在成本中。报告分别给出已知费用小计、未知次数和总费用；存在任何未知调用时总费用及每个通过任务的费用保持未知。这里统计模型 token 调用的估算费用，不包含浏览器、数据库或托管费用。

## 指标定义

| 指标 | 定义 |
| --- | --- |
| 行为通过率 | 全部固定断言通过且无运行错误的任务数 / 全部预定任务数；生成失败、阻断及预算跳过不能从分母消失 |
| 修改回归通过率 | 新需求及全部旧断言都通过的修改数 / 全部预定修改数 |
| 旧功能断言通过率 | 通过的旧行为断言数 / 全部旧行为断言数；另列「此前通过、现在失败」的断言 |
| 耗时 | 单个步骤从规划开始到浏览器检查结束，含失败、修正、浏览器启动；分别记录 generationMs、behaviorMs 和总 durationMs，报告 P50 / P95 与原始分布 |
| 修复次数 | 实际进入无效代码自动修正的次数，包含修正后仍失败的任务；每个步骤最多一次，无手动重试或行为修复 |
| 调用成本 | 全部规划、生成、失败、修正的 usage × 指定版本单价；每个通过任务成本 = 可计算总费用 / 通过任务数 |

一条链如果没有产生静态合法代码，后续修改记为 `BASELINE_UNAVAILABLE`，保留在分母内。静态合法但行为失败的代码仍进入下一步修改，符合当前线上「静态校验后保存」的行为。重试整轮必须使用新运行目录，不覆盖原始失败记录。

耗时分位数使用最近秩法；阻断 / 预算跳过的任务没有执行耗时，不参与耗时分位数。已执行任务与通过任务分别汇总，小样本需要查看原始记录。每一步在全新 iframe 运行，不测内存业务记录跨源码版本迁移，也不测 API、保存、Restore、权限或网络恢复；这些仍由现有工作流回归测试覆盖。

## 输出与复现

评测任务同时提供结构化目标、数据字段、保留项与独立验收动作。report.json / results.jsonl记录taskContract、taskFingerprint和脱敏toolTrace，每任务artifact保存task.json；生成、静态检查及离线run_checks通过同一受控注册表执行。工具输入、权限、预算和失败分类见[任务与工具契约](../TASK_TOOL_CONTRACT.md)。

默认输出到被 Git 忽略的 `eval-results/<run-id>/`：

- `report.md`：可阅读的汇总、每任务结果和统计口径。
- `report.json`：完整元数据、汇总、任务、断言和每次模型调用。
- `results.jsonl`：每完成一个步骤追加一条记录，保留失败结果。
- `tasks.csv` / `calls.csv`：任务指标与逐调用 usage / 成本，UTF-8 BOM，可用 Excel 打开。
- `suite.json`：本轮任务提示词及断言清单。
- `artifacts/`：各轮完整源码、计划和失败截图。

报告记录任务集版本、提示词版本、任务与代码 SHA-256、Git commit / 修改状态、模型协议配置、各调用输出预算、单价版本、重复次数和执行预算。比较两次结果应保持任务、模型、参数、重复次数和预算一致，明确代码指纹的变化；固定任务提示词调整后需要更新 `SUITE_VERSION`，不能继续当作同一基线。首次样例通过只能证明评测框架可运行，真实模型质量需要另跑 `--mode live`。

浏览器子进程只接收生成代码和测试参数，使用最小环境变量，不继承模型或 Supabase 凭据；页面网络请求全部阻止，应用使用当前 `composePreview` 和 `sandbox="allow-scripts"`。这是可终止的本地评测进程，仍不是用于公开执行任意代码的生产隔离平台。

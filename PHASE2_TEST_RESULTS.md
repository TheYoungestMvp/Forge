## Issues found and resolved

- The configured DeepSeek Chat Completions endpoint supports json_object, rather than json_schema. Non-secret configuration was corrected; exact four-field server validation remains mandatory. An explicit LLM_MAX_TOKENS_FIELD setting supports max_tokens without changing the default for newer compatible services.
- Calculator's first reasoning-mode response exceeded the 12000-token output budget. The UI displayed OUTPUT_TRUNCATED. Optional LLM_THINKING_MODE=disabled now allows this DeepSeek demo to reserve its budget for application code. Other services can omit the setting; the adapter then sends no thinking parameter.
- A later calculator output incorrectly appended the second operand, making 7+5 return 82. The generation system prompt now specifies operand state and concrete arithmetic checks. A fresh initial generation, with no supplied previous code, passed all five arithmetic checks. The generated code was not manually repaired.
- The host preview wrapper interfered with generated body flex layouts. display:contents removes its layout box while retaining the app mount point. Todo and Habit Tracker interaction and narrow-screen checks passed again after this fix; Calculator also passed with the final wrapper.

Todo and Habit Tracker acceptance used their original successful reasoning-mode responses. Calculator acceptance used the final non-thinking configuration. The final default example configuration uses JSON mode, max_tokens and disabled thinking.

Static validation proves shape and supported code constraints, not arbitrary application correctness. These functional checks cover the three observed model-generated outputs; subsequent generations may differ and should be verified through Preview.
